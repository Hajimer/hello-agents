# Hello-Agents 个人学习工作区

学习期间：2026-10-14 至 2026-11-30。第一阶段截止日期：2026-11-30。

教材：[Datawhale Hello-Agents](https://github.com/datawhalechina/hello-agents)，也可通过[在线教材](https://datawhalechina.github.io/hello-agents/)阅读。

## 学习目标与边界

亲自理解并实现 Agent Runtime，培养独立编程、调试和架构设计能力。已有使用 AI Coding 工具完成项目的经验，本次重点是自己形成方案、手动实现并验证，而非依赖 AI 生成可运行结果。

本目录与原仓库隔离：`../docs/` 是教材，`../code/` 是配套示例，均作为只读参考。助手担任技术导师、答疑助手和代码审查者，具体约束见 [AGENTS.md](AGENTS.md)。

## 目录用途

- `python/`：自己手动编写的 Python 实现。
- `go/`：自己手动编写的 Go 实现。
- `notes/`：个人技术笔记与实验记录。
- [PROGRESS.md](PROGRESS.md)：轻量学习进度与验证证据。

初始化只包含目录与说明文件；实现、测试及环境配置留待学习过程中按实际需要自行完成。

## 学习方法

在浏览器阅读教材，在本地逐行手动编写、调试和测试重要代码。对重要内容遵循四步学习法：

1. 阅读教材并手动实现，理解每段代码。
2. 关闭教程，仅根据功能描述独立重建。
3. 主动构造边界情况、错误输入和异常场景。
4. 再对照 Hello-Agents 或成熟实现，分析设计差异与 Trade-off。

遇到问题时携带自己的思路、相关代码、实际结果与预期结果向助手提问，默认先获得方向提示。简单语法和概念可以直接询问。

技术设计决策日志在 Notion 中独立维护，结构为 Problem / My Solution / Alternative / Trade-off；此处不重复建立另一套日志。

## 阶段安排

以下按学习顺序推进，不设未经确认的逐周任务。阶段进度依据理解、独立重建与验证证据判断。

| 顺序 | 学习范围 | 阶段目标 |
| --- | --- | --- |
| 1 | 第 3、4 章 | 理解 LLM 基础与 ReAct、Planning（教材 Plan-and-Solve）、Reflection |
| 2 | 第 7 章 | 不使用现成 Agent 框架，独立实现 Python Agent Runtime |
| 3 | 第 9、8、10、12 章 | 学习 Context、Memory、RAG、通信协议与 Evaluation |
| 4 | Go 基础与 Runtime 重建 | 根据行为需求独立重建 Go Agent Runtime |
| 5 | 成熟框架与第 16 章综合实践 | 在独立实现之后分析框架，完成小型综合 Agent 应用 |
| 6 | 真实 Eino 项目「舌鉴」 | 进行架构分析与技术复盘 |

独立设计与实现、正确性验证、异常处理，优先于机械完成所有扩展案例。

## 核心交付物与验收方向

| 交付物 | 验收重点 |
| --- | --- |
| Python Agent Runtime | 能解释执行流程，脱离教材重建，用测试验证核心行为与异常处理 |
| Go Agent Runtime | 根据行为需求独立设计实现，能说明语言与设计选择，验证核心行为 |
| 综合 Agent 实践项目 | 将所学用于小型应用，能解释架构、技术选择与验证结果 |
| 舌鉴架构复盘报告 | 结合真实 Eino 项目分析架构、设计差异与 Trade-off |

Python 与 Go Runtime 都应能用 Mock LLM 响应测试 Agent Loop，基础测试不依赖真实模型接口。“程序运行成功”仅是一项证据，还需能独立重建、解释设计并处理异常。

## 开始使用

自行阅读教材后，在 `python/` 中手动创建自己的 `.py` 文件并逐行编写。文件名和组织方式由自己按当前学习内容决定，无需先建立框架或完整工程结构。

完成一项实际学习活动后，在 `PROGRESS.md` 中记录对应状态与证据；未完成的状态保持未勾选。
